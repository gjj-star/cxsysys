# 个人中心接口适配核查

> 后续适配已完成，结果见[实现与验证记录](personal-center-implementation-2026-11-13.md)。下文保留开发前核查时的状态与建议。

核查日期：2026-11-13。范围是用户截图框出的 6 个个人中心操作，以及通用上传、文件获取，共 8 个操作；划线的帮助、反馈接口不在本次适配范围。

本轮仅阅读、导出接口定义和验证只读请求，没有修改业务代码，也没有调用修改资料、改密、上传、退出等写接口。已有 `gradle.properties` 用户修改保持原样。

## 结论

可以保留现有“我的”页、个人信息页、企业管理页和修改密码页的布局、主题及导航，补齐数据绑定和操作事件。需要增加的可见交互主要是头像选择/清除、成员列表及加载更多、请求中的按钮状态、失败提示。

接口名称“修改个人资料”容易造成误解：实际只允许写 `avatar_url`，姓名、手机号、用户名、企业、部门等均只读。当前页面的“认证状态”没有对应的认证字段；`status` 是账号启用状态，建议仅把该行文案改为“账号状态”，不能把账号正常显示成已实名认证。

## 阅读依据与现有开发习惯

已分工逐文件通读仓库全部 9 个 Markdown 文档、97 个 Kotlin/Java 源文件（含测试，20,745 行），并核对构建配置、Manifest、XML 资源和调试配置。第三方 SDK 二进制、生成目录不作为自有源码阅读。

- 主 App 使用 Compose + Material3、ViewModel + StateFlow、协程和 Retrofit；ViewModel 直接调用网络服务，没有实际 Repository/DI 层。打印库独立使用 Java Activity/XML，个人中心接入无需改动打印业务。
- 页面沿用绿色标题栏、灰底白卡片和现有路由。请求失败复用 `orErrorMessage` / `toUserMessage`，成功后刷新数据及 Toast，失败保留输入。
- 实际鉴权是自定义 `token` 请求头，资料持久化是 SharedPreferences。历史实施文档中 DataStore / Authorization 的描述不代表当前实现。
- 可复用 `PhotoSourcePickerDialog`、`rememberCameraPhotoLauncher`、现有 Uri 转文件方式及 Coil 图片显示。无需新增裁剪页面或图片选择库。

## 页面与接口映射

所有路径均相对本地业务基址 `https://dbcx.org.cn/planting/api/v1/`。

| 现有区域 | 接口 | 最小适配 |
| --- | --- | --- |
| “我的”页头部、个人信息页 | `GET /user` | 获取最新姓名、手机号、用户名、头像、企业名称、角色等，替换缓存/横线占位；保留现有行和卡片。头像为空或不可读取时沿用默认图标。 |
| 头像行 | `POST /upload`，multipart `file` + `type=avatar` | 点击原有头像行，复用拍照/相册选择；上传成功即已持久化当前用户头像，随后刷新 `GET /user`，不必重复提交同一头像链接。 |
| 清除或设置本人头像 | `PUT /user`，JSON `avatar_url` | 可在头像选择弹窗增加“清除头像”；发送 `avatar_url: null`。若绑定已有文件，必须是本人上传的头像。其余资料不提供编辑输入。 |
| 本人头像显示 | `GET /files/{relative_path}` | 返回图片字节，不是 `BaseResponse`；携带当前用户 `token`。优先直接使用 `data.file_url`，保留多级目录斜杠。 |
| 修改密码页 | `PUT /user/password` | 原有旧密码、新密码、确认密码三输入框及按钮直接接入；字段为 `old_password`、`new_password`、`confirm_password`。 |
| 企业信息卡片 | `GET /user/enterprise` | 将现有企业名称、企业 ID、联系电话、企业地址四行绑定真实值。接口额外的企业类型不必为接接口而新增一行。 |
| 企业页“成员管理”卡片 | `GET /user/enterprise/memberList` | 占位文案替换成姓名/用户名、角色的只读列表，在原卡片内分页；首次不传 `lastid`，下一页用最后一条 `user_id`，结合顶层 `hasMore` 加载更多。 |
| 退出按钮和原确认框 | `POST /user/logout` | 先携带现有 token 发请求，再清除本地 token、用户缓存和页面状态，回到现有登录页。401 也视为本地可退出；断网仍应允许本地退出，并说明服务端注销未确认。 |

个人信息对应字段：姓名 `real_name`（空时回落 `user_name`）、手机 `phone_number`、用户名 `user_name`、所属企业 `enterprise_name`、角色 `roles[].role_name`（超级管理员可保留现有标识）、账号状态 `status`。空值应显示现有横线或默认头像。性别、脱敏身份证、部门和雇佣日期虽然已返回，但为了少改 UI，不必全部增加到页面。

企业成员接口只有简要资料和 `dept_id`，没有成员手机号、部门名或增删改接口；不应额外设计这些功能。文件接口只允许创建者读取，连超级管理员也不能读取其他成员的文件，因此成员头像使用默认图标即可，不能直接拿成员的 `avatar_url` 批量请求。

## 必须连同处理的少量逻辑

1. **共享并刷新用户状态。** `AuthApiService` 已声明 `GET user`，但 `AuthViewModel` 没有调用；“我的”目前来自登录响应/缓存。复用该方法并增补模型，资料更新后同步 AuthState 与 TokenManager。让“我的”和个人信息页共用同一份用户状态，避免返回后仍显示旧头像；导航只需传递同一实例或明确刷新，无需重写导航。
2. **保持清除头像的显式 null。** 合约要求提交 `avatar_url: null`；默认 Gson 会省略普通对象的 null 属性，应对这个请求单独保证发送 null，避免改动全局序列化而影响其他录入接口。
3. **头像鉴权和缓存。** 普通 `AsyncImage(url)` 不会经过业务 Retrofit 的鉴权拦截器。只对可信业务文件地址携带 token，禁止跨域重定向继续携带该自定义请求头；按用户隔离图片状态/缓存，切换账号或退出后清理，避免沿用前一个用户的头像。文件 403 不等于登录失效，不应因此强制退出。
4. **密码校验与会话。** 新密码至少 6 位、UTF-8 不超过 72 字节，两次输入一致，且不同于旧密码；不修改用户输入的空格。普通用户改密成功后后端使旧 token 失效，前端清登录态重新登录；旧密码错误或网络失败保留表单。超级管理员的预置 token 是后端例外，不能用它验证普通账号失效行为。
5. **错误和重复提交。** 使用现有中文错误工具，加载失败提供重试，提交时禁用重复操作；401 的会话失效处理只适用于已登录业务请求，不要把匿名登录的账号密码错误当作会话过期。退出/改密后清除个人与企业页面状态，处理旧请求晚到的响应，避免恢复旧账户资料。
6. **敏感请求日志。** 当前业务客户端开启 BODY 日志，只遮蔽 token 请求头。接入改密时需要对敏感请求关闭正文日志或脱敏，避免旧/新密码进入日志；无需改变页面样式。

## 建议修改范围

- 扩展既有 `AuthApiService.kt`、`AuthModels.kt` 和 `AuthViewModel.kt`，复用现有 `getCurrentUser()`，不再增加一份同名用户获取接口。
- 为企业信息/成员列表增加小型 ViewModel 与数据模型，沿用当前网络/状态风格。
- 给现有通用上传补头像类型参数，保留其他业务调用的默认行为；复用照片组件，补一个带鉴权的头像加载实现。
- 在 `MineScreen.kt`、`ProfileInfoScreen.kt`、`EnterpriseScreen.kt`、`ChangePasswordScreen.kt` 局部绑定数据和按钮事件；`MainScreen.kt` 只处理必要的共享状态/返回登录。
- 根据资料持久化需要小幅扩展 `TokenManager.kt`；敏感请求日志在现有网络工具中局部处理。

设置页的通知、自动同步、位置服务、缓存、备份、语言和主题没有这批 API 支持；帮助/反馈按用户要求忽略；关于页继续使用本地版本信息。打印 SDK 与其他业务页面不在适配范围。

## 线上只读验证

使用当前配置的开发身份，仅发 GET，不在核查结果中保存真实用户资料或 token。

| 请求 | 实测结果 |
| --- | --- |
| `GET /user` | HTTP 200，业务 code 200；返回的 15 个用户字段与导出结构一致。 |
| `GET /user/enterprise` | HTTP 200，业务 code 200；返回企业 ID、名称、类型、电话、地址。 |
| `GET /user/enterprise/memberList?limit=2` | HTTP 200，业务 code 200；返回 2 条记录、顶层 `hasMore=true`，成员字段与合约一致。 |
| `GET 当前用户 avatar_url` | HTTP 200，`image/png`；TLS 验证通过。 |

Apifox 多个描述仍保留“设计文档，待后端实现”字样，属于文档与上线信息不同步；本次只读验证证明上述 GET 已可用。修改资料、上传、改密、退出的真实副作用尚未验证，后续实现时需用专门测试账号验收。

当前用户配置 `enableSuperToken=true`，Activity 启动会再次注入超级管理员身份并覆盖缓存。资料刷新、退出、重启和改密失效应关闭该调试开关后用普通账号验收；本轮没有代为修改用户配置。

接口快照：[personal-center-2026-11-13.openapi.json](personal-center-2026-11-13.openapi.json)。已筛选至本次 8 个操作，去掉请求头 token 的测试示例与默认值，保留接口原文及历史状态描述。

- 更换/清除头像的真实保存、刷新与重启；本人图片可读取，成员头像无权限时保持默认图标。

- 企业空字段、成员空列表、分页、加载失败；切换账号不残留上一账户数据。
- 正常/重复/断网退出、401；后续请求不再携带被清除的本地凭据。
